Audit records contain actor/time/article ID/action and safe publication status only, never bodies.

## Publication and date semantics

Save changes only a working copy. Publish validates and atomically replaces the separate last-published snapshot, its selection date/Featured values, status, timestamp, optimistic version and audit. Subsequent title/body/date/Featured edits cannot change public reads until Publish. Unpublish removes eligibility, retaining the working copy, last snapshot and audit events; this is not a complete revision archive.

Publication date is an explicit **UTC instant**, not a schedule; input offsets normalize to UTC. Draft future dates are allowed, but Publish rejects instants later than current database wall-clock time after the lock is obtained. Public readers additionally reject future published dates and malformed/inconsistent snapshots. The homepage query orders published snapshots by **Featured descending, publication instant descending, stable ASCII slug ascending (`C` collation)**, caps at four and excludes the body from its DB projection. No draft fields/IDs/versions/people data enter that public DTO. Publication changes request homepage revalidation after commit; an unconfirmed refresh reports persisted state accurately. No live CDN invalidation is certified by local checks.
