## Configuration and later owner setup

All values are **server-only**, never `NEXT_PUBLIC_*`. The empty names are documented in [`.env.example`](../../.env.example); no credentials are committed or configured.

| Variable | Required value / behavior |
| --- | --- |
| `RESEND_API_KEY` | A secret Resend **sending-access** key, restricted to the approved verified sender domain. Missing, empty, oversized or whitespace/control-containing values disable the transport. Never use a full-access key unnecessarily or paste one into chat/logs. |
| `ADMIN_INVITATION_FROM` | The approved **bare email address** on that domain. The adapter supplies `NOSEE <address>`; do not put a display name, angle brackets or extra recipients in this variable. Missing/invalid address disables the transport. |
| `ADMIN_ORIGIN` | Existing exact **HTTPS** admin origin, without path or trailing slash; it determines the template's token-free `/admin/accept-invitation` link. Mail remains unavailable for missing/invalid/non-HTTPS origins. Existing loopback authentication/test support is unchanged. |

Existing `DATABASE_URL` and `BETTER_AUTH_SECRET` remain required for authenticated administration. Do not replace their values, rotate the auth secret, attach a preview to the owner's database or bootstrap another initial administrator. This branch adds **no schema migration or dependency**. It requires the already-existing A02 schema, but does not apply it to any live database.

## Transport and failure semantics

- `src/lib/admin/resend-mail.ts` is server-only and uses built-in `fetch`, fixed `POST https://api.resend.com/emails`, bearer authentication, JSON HTML/text, `cache: no-store` and redirect rejection. No Resend SDK, logging, account/domain management or webhook integration is added.
- The existing persisted **send-attempt UUID** is passed through the neutral transport interface. The header is `Idempotency-Key: nosee-admin-invitation/<attempt UUID>` (well below the documented 256-character maximum). Repeating an identical attempt uses the same key/body. An explicit resend retains A02's existing code rotation and new send record/key. Never replace this key with a secret code, recipient, timestamp or a fresh UUID for each retry.
- There are **no automatic retries**, including for 429, network errors or 5xx. This avoids retry storms, duplicate messages and secret-bearing persisted retry payloads. Resend's idempotency protection is bounded by its provider retention; it is not a permanent exactly-once guarantee. The app does not retain a plaintext message/code to replay later. Existing duplicate/pending-invitation checks and explicit reissue safeguards remain intact.
- An independent **8-second** request deadline combines with caller cancellation, inside A02's existing 10-second outer ceiling. Network/abort/decoding errors, HTTP 408/409/5xx, redirects, malformed or unexpected success responses are **unconfirmed**. A message may already have been accepted; no blind retry or false successful-delivery claim is made.
- Only HTTP **200** with a nonempty, bounded safe email ID records **accepted by provider** and the provider ID. The official API specifies a string ID; no undocumented UUID-only restriction is imposed. Reflected content/credential IDs are discarded, and the existing service also checks IDs against the invitation code. Acceptance is never called confirmed inbox delivery. No delivery webhook is implemented or implied.
- Explicit HTTP 400/401/403/404/405/413/415/422/429 rejection records **failed** through the existing service, revoking that attempt's token. A 429 does not trigger a sleep/retry; inspect the account/rate limit before choosing an explicit resend. That action creates a new code and attempt; the older code stays unusable.
- Provider error bodies/headers and thrown error messages are discarded. The adapter returns only the neutral status and validated acceptance ID. No API key or invitation code appears in URLs, audit records, logs or administrator responses. Existing creation, 48-hour expiration, atomic redemption, revocation, token rotation, no-public-signup policy, template copy/design and A06 Lead restriction are unchanged.
