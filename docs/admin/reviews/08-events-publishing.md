## Six owner walkthroughs

Use securely supplied existing Preview accounts and synthetic content. Test at desktop and mobile widths; keep credentials out of review comments.

1. **Draft/direct publish — Editor:** open `/admin/publishing/events`, Add event, enter title/summary/description/organiser and venue, save a draft, then preview it. Its public URL remains 404. Publish it, then add a second event using Publish directly; both appear publicly without a scheduled-publication wait.
2. **Schedules/zone — Editor:** enter a future single-day/overnight schedule, switch to multi-day with a later end date and add itinerary/deadline. WAT is default; changing zone displays the same instants. Check end-before-start/out-of-range itinerary/deadline errors. Try a nonexistent DST local time; it must fail, while the repeated autumn hour follows the documented earlier-occurrence rule.
3. **Public/homepage/meeting — Editor:** inspect an ordinary event's detail, time/zone, location/resources and archive/search/type filters. Publish a meeting with a safe site URL and open `/events/its-slug`; expect 302 to that stored destination. Publish four upcoming events with mixed Featured values; homepage shows at most three, Featured first then nearest start, and drops each on refresh once its start is reached, without an admin save.
4. **Saved revisions — Editor:** publish, change summary/body/schedule and Save as draft. Directory shows Published · Unpublished changes, while public details/homepage/redirect still use the old snapshot. Revert and save to clear the badge, then change/save/Publish changes; the badge clears and the site updates.
5. **Unpublish/delete — Editor or Super Admin:** unpublish to remove public details/homepage/meeting redirect, then republish. At Edit's bottom choose Delete event; Cancel, Escape and backdrop dismiss safely. A wrong phrase cannot submit; exact `Delete {event title}` removes it permanently, preserves audit history and reserves the URL. A stale editor cannot restore it.
6. **Roles — Super Admin/Editor/Lead:** confirm both publishing roles can search/filter/page, edit, preview and publish. A Research Group Lead opening Events pages or APIs receives denial. Signed-out pages redirect to sign-in and APIs deny access. Confirm the News/password workflows still behave normally; unrelated earlier acceptance is not inferred.
