## 1. High-priority issues to address (owner approval for task execution required)

**A. Mobile LCP and homepage image payload.** Task 10 measured Lighthouse **15.084 s** mobile LCP; direct throttled CDP **18.772 s**, and initial homepage image bodies around **3,936,230 B** (first-slide on slow connection ~2.44 MB). Identify actual LCP element/request waterfall. Apply **small, visually equivalent responsive image optimization** to the source raster images with relevant \`srcset\`/\`sizes\`/modern compression and correct decoding/discovery/priority; reduce offscreen downloads where this won't change actual hero autoplay/swipe. Reuse existing assets/framings; preserve exact source text, slide order, crop/geometry, hero entrance timing, interaction and first-frame appearance. Avoid changing unrelated page semantics or client hydration. Keep original files only if still referenced/needed, record any intended asset variant substitutions. Verify no broken first image, transition blank frames, mobile/desktop crops, CTS/CLS/visual artifacts. Measure mobile cold transfer bytes, request counts, LCP and CLS with **the same three-run Lighthouse and three-run direct CDP throttling profiles used in Task 10**, and report before/after medians and raw ranges. A target LCP of ≤2.5 s remains the performance goal, **not permission to fabricate results or overcompress images**. If significant improvement isn't possible safely in this PR, quantify the blocker and stop instead of speculative changes.

**B. Text contrast (actual WCAG failures).** On relevant dark footer surfaces, Task 10 recorded **#5c5c5c on #171717 = 2.68:1**, three nodes/page; the Events meeting badge **4.14:1**, below 4.5:1 normal-text threshold. Make the smallest permitted text/badge foreground or surface-token adjustments that reach ≥4.5:1 and remain brand-compatible; evaluate contrast in computed CSS and screenshots. No unrelated brand colour overhaul. Because MingCute uses \`currentColor\`, its icons must update to **the same neighbouring text colour**, including hover/focus and white/dark variants.

**C. Accessible names and search focus.** Task 10 reported homepage accessible-name/visible-label mismatches (**11 desktop/seven mobile**). Identify exact affected controls and align their programmatic names with visible names without changing the original visible public copy or navigation destinations. Add an obvious, keyboard-visible Events search-input focus style to the existing shadcn-free native form (source lacked focus feedback); keep search query encoding/results/GET semantics unchanged. Don't insert icon or decoration unrelated to this.

**D. Mobile navigation and fragment fallback without JS.** Task 10 confirmed source's mobile menu/toggle unusable without JS, hidden close control, and headings obscured by direct fragments. Implement the smallest progressive-enhancement fallback preserving existing JS-enabled nav geometry, drawer/submenu semantics, keyboard/Escape/focus return, SSR, route semantics, scroll compact/expanded states, reduced motion and MingCute icon styles. Test no-JS at 320, 390, 768, and JS-enabled mobile/tablet/desktop. Adjust anchor scroll offsets only where measured heading clipping exists; do not modify other section geometry. Report any limited unavoidable UI changes.

**Do NOT include in this PR:** mixed \`?q=x&q[]\` PHP parser edge-case (medium), carousel indicator hit-target sizes (medium), 320px Events horizontal overflow (medium), admin/auth, unimplemented \`/news\`/\`/publications\`/\`/data\` routes, content fixtures/DOIs/biographies, indexing, newsletter integration, icon-pack substitutions, generic refactors or speculative performance work. Record these as tracked follow-ups. If a medium finding blocks correct implementation of an authorised high item, document it first.
